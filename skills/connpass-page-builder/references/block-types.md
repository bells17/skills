# ブロックの判定と構造

見出し名やセクション数は固定しない。Markdownの内容を次の3種類へ分類し、対応するHTMLテンプレートを必要な回数だけ使う。例はすべて架空の「サンプルミートアップ」のもの。全体の入力は[sample-input.md](sample-input.md)を参照する。

| 分類 | テンプレート | 判定の手がかり |
| --- | --- | --- |
| Standard（その他） | [standard.html](../templates/standard.html) | 通常の文章、参加対象、案内、注意事項など |
| Timetable（タイムテーブル） | [timetable.html](../templates/timetable.html) | 時刻と予定内容が繰り返し対応する表・リスト |
| Session（登壇内容） | [session.html](../templates/session.html) | 個々の発表タイトル、登壇者、概要や画像がまとまった節 |

テンプレートの`{{...}}`はLLMが内容を当てはめる位置を示し、実行用のテンプレート言語ではない。必要なバリエーションだけを選び、任意要素・繰り返しの指示コメントや未展開の変数を完成HTMLに残さない。`*_html`には安全に構成したHTML、それ以外には適切にエスケープした文字列を入れる。詳しい変数と省略条件は各テンプレートのコメントを読む。

## Standard Block（その他）

通常の説明、参加対象、配信、会場案内、注意事項、行動規範、連絡先など。特殊ブロックと判定できない内容もここで扱う。見出し名から定型文や欠けた節を補わない。

```markdown
# この交流会について
**データ収集・可視化・チーム開発**の工夫を共有します。

# 参加してほしい方
- サンプルデータの収集や可視化に興味がある方
- [サンプルコミュニティの活動](https://example.com/sample-meetup)を知りたい方

## 会場への入り方
受付は18:30から開始します。
```

通常は`standard.html`の区切り線付き見出しと本文を使う。見出しの文字列はそのまま移し、段落は`p`、箇条書きは`ul` / `ol`と`li`、リンクは`a`、強調は`strong` / `em`、画像は`img`に移す。文章・リンク・順序を保持する。

通常見出しは22px、階層上の下位見出しは19px、本文は16px。通常見出しの上marginは30px、ページ先頭なら18px。下位見出しは24px。特定の見出し語に応じて独自のサイズを追加しない。

参加対象を列挙する節には、同じテンプレート内の枠付きバリエーション（17px見出し、16pxリスト、16px 20px padding）を選ぶ。「参加してほしい方」「こんな方におすすめ」など表現が異なっても意味で判定する。注意事項など別の目的のリストまで枠で囲まない。対象者の節に文章やリンクがあれば、それも順序どおり残す。

| 内容から読み取れる目的 | 自動選択する表示 |
| --- | --- |
| 参加を勧める人の関心・経験・立場を列挙 | 枠付き表示。見出しが「ご案内」でも同じ |
| 開催趣旨、配信方法、受付手順、持ち物、注意事項など | 通常の見出し＋本文。箇条書きでも枠は付けない |
| 目的が不明、太字があるだけ、見出しと内容が一致しない | 本文の意味を優先し、参加対象と判断できなければ通常表示 |

この枠は自動判定では参加対象向けに使う。「重要そう」という主観だけで他の内容を囲まない。ユーザーが別の箇所を枠で強調するよう明示した場合は、同じ枠のデザインを使い、文章や順序は維持する。

## Timetable Block（タイムテーブル）

時刻と予定内容が対応して繰り返される表・リストを判定対象とする。「当日のスケジュール」「進行」などの見出しでも該当する。受付開始時刻を一文で説明しているだけならStandardのまま。

```markdown
# 当日のスケジュール
| 時間 | 内容 | スピーカー |
| --- | --- | --- |
| 19:00-19:05 | オープニング | サンプル運営チーム |
| 19:05-19:25 | セッション1 サンプルセッション1 | サンプル株式会社 登壇者A ([@speaker_a](https://example.com/people/speaker-a)) |
| 19:25-19:45 | セッション2 TBD | サンプル合同会社 [@speaker_b](https://example.com/people/speaker-b) |
| 19:45-19:50 | 休憩 | |
```

各行から開始・終了時刻、タイトル、氏名、所属、SNSリンク、種別を取り出す。確実に分離できない所属・氏名は元のまとまりで保持する。種別は行のバリエーションを選ぶために使い、記載のない種別名を本文に追加しない。

`timetable.html`の見出しはブロックの役割に基づき22px（入力が`##`でも同じ）、上marginは32px、ページ先頭なら18px。入力に見出しがなければ省く。`table > tbody > tr > td`による2列構造を使い、左が時間、右がタイトルと登壇者。最初の行の20% / 80%指定、固定テーブル、罫線、セルpaddingを保つ。

| 行の用途 | テンプレートの表示 |
| --- | --- |
| 通常セッション | 時間14px太字、タイトル18px太字＋記号、登壇者13px |
| オープニング・LT・エンディングなど | 時間14px、タイトル17px、登壇者13px |
| 休憩 | 時間14px、内容15px、上下padding 7px |

登壇者情報がない行には空の登壇者`div`を追加しない。時間が片方しかなければ、存在する時刻だけ表示する。未記載の終了時刻を次の行から算出しない。会場や備考など追加列にある情報は右セル内に保持する。行を種類別や時刻順に並べ替えない。

「セッション1」のような構造上の接頭辞は、対応する詳細の「発表1」に番号を表示する場合、表のタイトルから分離できる。詳細がないなど、番号を移す場所がない場合は表にも保持する。タイトル自体に含まれる数字や文字は削除しない。

## Session Block（登壇内容）

発表タイトルと登壇者、概要、プロフィール画像などがまとまった節。表中の短い予定行だけならTimetableであり、勝手に詳細を複製しない。親見出しが「発表の詳細」などでも同じブロックを使い、元の見出しと導入文を残す。

```markdown
## 発表の詳細
### セッション1: サンプルセッション1 (サンプル株式会社 登壇者A ([@speaker_a](https://example.com/people/speaker-a)))
![登壇者A](https://example.com/images/speaker-a.png)

小さな収集システムで試した再送処理と記録方法を紹介します。

### セッション2: TBD (サンプル合同会社 [@speaker_b](https://example.com/people/speaker-b))
![登壇者B](https://example.com/images/speaker-b.png)

### セッション3: サンプルセッション3(仮) (サンプル開発チーム 登壇者C ([@speaker_c](https://example.com/people/speaker-c)))
3人の開発チームで続けている習慣を紹介します。
```

発表番号、時刻、タイトル、氏名、所属、SNSリンク、サムネイルURL、概要を抽出する。括弧が入れ子になった見出しでは、タイトルの`(仮)`などを登壇者情報と誤認しない。別節のタイムテーブルとの対応が一意なら、そこに明記された時刻を表示できる。情報が衝突する場合は書き換えず報告する。

`session.html`の親見出しは入力にある場合だけ使う。ブロックの役割に基づき22px（入力が`##`でも同じ）、上marginは34px、ページ先頭なら18px。各発表の外枠は件数分繰り返し、下margin 24px、下padding 24px、1pxの区切り線を維持する。内容は次の順に置く。

1. 記号・発表番号・時間：15px、Accent、下margin 8px。
2. タイトル：21px太字、Navy、行高1.5、下margin 14px。
3. サムネイル：幅96px、高さ自動、2px枠、5px角丸、3px padding。
4. 氏名とSNSリンク：17px太字、写真の下に独立した`div`。
5. 所属：14px、補助文字色、氏名の下に独立した`div`。
6. 概要：16px、行高1.7。段落が複数なら最後以外の下margin 12px、最後は0。

概要があるプロフィール枠は下margin 14px、概要がなければその余白と概要枠を省く。画像がなければ画像要素だけを省き、氏名・所属を残す。上の例ではセッション2の概要とセッション3の画像を補わない。プロフィールのない発表や概要だけの発表も、存在する情報だけで組む。最後のセッションにも区切り線を残す。写真と文字を横並びにせず、Flexbox、Grid、プロフィール用テーブルは使わない。

複数登壇者は元の並びで、各人物の写真・氏名・所属を縦に繰り返す。複数画像やSNSリンク、概要内のリスト・強調など、主要項目に収まらない内容も元の順序と関係を維持する。

## 不明な構造と混在

一つの節に通常の文章、時間表、詳細が混在すれば、連続するそれぞれの内容に対応するブロックを当てる。ページ全体を種類ごとに並べ替えない。分類が不確かな表・引用・コードなどはStandard内に安全な構造で保持する。コードや生HTMLを実行しない。テンプレートにない表現のために新たな装飾を足さず、既存の本文スタイルを用いる。
